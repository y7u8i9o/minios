# Plan: a modern terminal userland

## Context

The shell reads lines with `fgets` in canonical mode (`user/sh/sh.c:857`): no cursor movement, history or completion, and the kernel keyboard driver drops arrow keys in canonical mode (`kernel/input/keyboard.c:113-118`). The shell language has no globbing, tilde, control flow, functions, aliases, `2>` or startup files, and the prompt is the hardcoded `cwd $ ` (`sh.c:853`). No utility uses colour or the terminal width, `ls` has only `-l -a`, `grep` matches fixed strings, and six manual pages exist. The framebuffer console drops SGR sequences (`kernel/drivers/fbcon.c` handles only `H f J K A B C D`), while the Terminal window (`user/term/vt.c`) supports 16, 256 and 24 bit colours. Nothing sets `HOME`; `TERM` is set only by the Terminal window.

The user chose: console colour (16 colours), the whole shell language in one branch, the core utilities with colour and manual pages. The development plan (`README.md`) is not touched; the design goes to `docs/design/`. Branch: `bleeding-edge-terminal` from `bleeding-edge`.

## Architecture

1. **Line editor as a library `libedit/`** (`include/edit.h`, `src/edit.c`, `keys.c`, `history.c`, `complete.c`; Makefile cloned from `libgui/Makefile`). Top level `Makefile`: `libedit: libc`, `user: ... libedit`; `user/Makefile`: `LIBEDIT`, `-I../libedit/include`, the library on the link lines. API: `edit_open(in, out)`, `edit_set_completer(e, cb, arg)`, `edit_readline(e, prompt, buf, size)` returning the length, `-EIO` at end of file, `-EINTR` on Ctrl+C, `edit_history_add/load/save`. Behaviour: if `poll` shows queued input, read one line in canonical mode (the tty ring contains only complete lines, `tty.c:78-83`), which allows every kernel test that types before the prompt to continue to work without double echo; otherwise clear `ICANON|ECHO|ISIG`, read byte by byte (as `user/edit/edit.c:296-303` does), restore termios before returning. Keys: Ctrl+A E B F K U W L P N D C H, Delete, arrows, Home, End, Tab, Alt+B/F, Ctrl+R reverse search, bracketed paste passthrough. Redraw uses only `\r`, `ESC[K`, `ESC[nC/D/A/B`, which fbcon already implements; multi row lines computed from `TIOCGWINSZ` re-read at each redraw; cursor arithmetic by code point with `mbrtowc` and a new `wcwidth`. Usable later by a mint REPL.

2. **Shell rewritten as a tree parser**: `user/sh/{sh.h, main.c, lexer.c, parser.c, expand.c, arith.c, exec.c, redirect.c, builtins.c, builtin_test.c, vars.c, jobs.c, prompt.c}`, each under 800 lines. `sh.h`: `enum node_kind { N_SIMPLE, N_PIPELINE, N_LIST, N_IF, N_FOR, N_WHILE, N_UNTIL, N_CASE, N_FUNCDEF, N_SUBSHELL, N_GROUP }`, `struct word` (unexpanded text with a quote map), `struct redir { fd; kind R_IN R_OUT R_APPEND R_DUPIN R_DUPOUT R_HEREDOC; target }`, `struct node { kind; words; redirs; a, b, c, next; op; bg; text }`. Lexer tokens: word, newline, io-number, `<< >> >& <& ( ) ;;`, reserved words only in command position. Recursive descent `parse_complete_command → list → and_or → pipeline → command → simple | compound`; the reader supplies continuation lines with `PS2`. Expansion at execution in POSIX order: tilde, parameters, `$(( ))`, `$( )`, field splitting on `IFS`, glob, quote removal. Variables in `vars.c` with a scope stack for `local`; `export` syncs `environ`. Functions in a table; `return`, `break`, `continue` through an exec status enum. Job control moves from `sh.c:254-431` to `jobs.c` unchanged, preserving the messages that `tests/cases/jobcontrol` and `shell2` pin. Builtins added: `test`/`[` (port `user/coreutils/test.c`), `echo` (`-n -e`), `read`, `shift`, `local`, `return`, `source`/`.`, `alias`/`unalias`, `eval`, `type`, `command`, `break`, `continue`, `history`, `:`. Redirections: `N>`, `N>>`, `N<`, `N>&M`, `N<&M`, `<<` and `<<-` here documents through a pipe. `help` retains the prefix `builtins: cd exit pwd export` pinned by `tests/cases/shell/expect`.

3. **libc**: `glob.h` and `fnmatch.h` (`libc/src/glob/{fnmatch.c,glob.c}`, directories walked with `opendir`, no symlinks in the VFS), `wcwidth`/`wcswidth` (`libc/src/wchar/wcwidth.c`), `getline`/`getdelim`, and `term.h` (`libc/src/term/term.c`): `term_use_color(fd)` (`isatty`, `TERM` set and not `dumb`, `NO_COLOR` unset), `term_columns(fd)` (`TIOCGWINSZ`, then `COLUMNS`, then 80), `term_sgr(color)`. Coreutils are single file builds, so the helper belongs in libc.

4. **Console SGR** in `kernel/drivers/fbcon.c`: an attribute byte per cell (foreground and background palette indices) beside `cells`, a 16 entry palette equal to `vt.c:12` so the console and the window match, current fg/bg/bold/reverse state, `case 'm'` in `fbcon_csi` for 0, 1, 22, 7, 27, 30-37, 39, 40-47, 49, 90-97, 100-107, `esc_args` widened to 8. Index 7 maps to the current `0xaaaaaa`, so uncoloured output is unchanged. Scroll and clear move and reset attributes. `fbcon_get_cell(col, row, &c, &attr)` for the test.

5. **Environment**: `user/init/init.c` sets `PATH=/bin HOME=/home USER=user SHELL=/bin/sh TERM=minios` before `execvp("sh")` (kernel tests continue to pass `PATH=/bin` only, so they see the plain prompt); `user/term/term.c` adds `HOME` and `USER` next to `TERM`. `HOME` is `/home` because `/home/desktop` already lives there and the Files places list calls it Home.

6. **Prompt and startup files** (`prompt.c`): `PS1` escapes `\u \h \w \W \$ \t \n \e \[ \] \\`; default `\w \$ ` renders exactly today's `/ $ `, so `tests/cases/shell/expect` remains valid; `PS2` default `> `. Interactive shells read `/etc/profile` (shipped from `user/etc/profile`) then `$HOME/.shrc` (`user/home/.shrc`, needs an explicit copy rule because `user/Makefile:22` skips dotfiles). `/etc/profile` sets `PAGER=less`, aliases `ll` and `la`, and a coloured `PS1` only when `TERM` is set; the trailing `$ ` remains in the default colour because `kernel/tests/test_gui.c:176-183` finds the prompt by bright pixels. History in `$HISTFILE` (default `$HOME/.sh_history`, `HISTSIZE` 500), loaded at start, saved at exit.

7. **Utilities**: `ls` (columns from `term_columns`, `-1 -C -l -h -a -t -r -S -d -F`, colours by `st_mode`, dates from `st_mtime` with `strftime`), `grep` on `regex.h` (`-E -F -i -n -v -c -l -r -h -H -w`, matches coloured through `regmatch_t`), `cat -n -b -s -A`, `head`/`tail` `-n -c`, `tail -f` by polling `fstat`, `ps` with aligned columns from `/dev/proc` (`kernel/sched/proc.c:312`), `tree` (`-L -a -d`, colours like `ls`), `df` from a new `/dev/mounts` devfs file (path, type, total and free blocks; `sb_ops` gains an optional `statfs`, implemented by mfs from its superblock and by FAT from the FSInfo count), `less` (from `pager.c`: `regex.h` search with `/ ? n N`, `-R -N -S`, SGR passthrough with zero width when truncating, `%` position, `g G q`) with `pager` retained as a two line wrapper that runs `less`; `man.c` defaults to `less`.

8. **Manual pages**: plain text in the existing layout for `sh ls grep cat head tail ps tree df less pager echo test alias read`, and `man7/index.7`; `man` without arguments prints the index through the existing `apropos` path (`man.c:113-149`).

## Kernel facts the editor relies on

No new termios flags: `struct termios` retains `c_lflag` with `ICANON ECHO ISIG` (`abi.h:152`, `tty.c:213`). The editor clears `ISIG` so Ctrl+C arrives as a byte (an ignored `SIGINT` would not interrupt `read`). Arrows, Home, End and Delete reach raw readers as `ESC[A` and the like (`keyboard.c:105-112`) and only there, so tests feed them after the `ICANON` wait. No cursor position report is needed. `SIGWINCH` remains ignored by default; the editor re-reads the size at each redraw. The pty uses the same line discipline (`kernel/drivers/pty.c:59`), so the Terminal window needs no change beyond the environment.

## Risks

- Pinned output: `tests/cases/shell/expect` (`^/ \$ `, `builtins: cd exit pwd export`, `status 0x300`), `jobcontrol`, `shell2`, `ctrlc`, `script`. Preserved by the default prompt, unchanged job messages and help prefix.
- The serial log carries escape bytes: colour is gated on `term_use_color`, and kernel tests run without `TERM`.
- `sh.c` is already at the size limit; the split comes first, features after.
- Tests can type ASCII only until `scancode_for` grows.
- `tail -f`, `read` and `less` search need `getline`; the here document and `$( )` need pipes, which exist.
