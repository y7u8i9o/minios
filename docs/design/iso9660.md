# ISO 9660

R5 of `docs/plan/release-0.5.0.md` adds the read only file system
`iso9660`, `kernel/fs/iso9660/iso9660.c`. It reads the images that xorriso
writes: ECMA-119 with the Rock Ridge extensions (RRIP 1.12 on SUSP 1.12),
or ECMA-119 alone. Joliet is not read. The live medium of R6 uses the file
system as its root.

## Origin

The search for the primary volume descriptor, the layouts of the volume
descriptor and of the directory record, the walk over the records of a
directory with the zero padding at the end of each logical block, the
names of the records with and without the Rock Ridge `NM` entry, and the
collection of the extents of a multi-extent file adapt
`common/fs/iso9660.s2.c` of Limine 10.8.5 (BSD 2-clause,
`third_party/limine/LICENSE`). The source file retains the copyright
notice. Limine reads one file by its path and stops the boot on an error.
The VFS operations, the inode numbers, SUSP (`SP`, `CE`, `ST`), the Rock
Ridge entries `PX`, `PN`, `SL`, `TF`, `RE` and `CL`, names that continue
over several `NM` entries, and the error returns are minios code.

## Mount

`mount iso9660 DEVICE DIR` mounts a block device, a CD drive (`sr0`) or a
disk with an ISO image written to it, such as a USB stick. The mount reads
the volume descriptors from logical sector 16 on, 2048 bytes each, until
the primary volume descriptor, and fails at the terminator, after 256
descriptors or at a descriptor without `CD001`. It takes the volume
identifier, the volume space size, the logical block size, which must be
2048, and the root directory record. Rock Ridge is in use when the
system use area of the root's "." record starts with `SP` and its check
bytes. `SP` also gives the bytes that every other system use area skips.
The log line is `sr1: volume ISOTEST, 1934 blocks, Rock Ridge`.

Every read goes through the block cache in blocks of 4 KiB, which works
for CD drives with 2048 byte sectors and for disks with 512 byte sectors.
The mount has no options, and every modifying operation fails with
`EROFS`.

## Inodes

An inode number is a byte position on the volume. A directory has the
position of its extent, where its "." record is, and every other file has
the position of its directory record. `read_inode` reads the record at
that position. A "." record is a directory, whose extent and size come
from the record. A regular file collects its extents: the record and the
records after it while each one has the multi-extent flag. A symbolic
link takes its target from its `SL` entries. The inode cache frees the
extent list and the target with the inode.

## Names and attributes

`parse_record` reads a directory record and its system use area.

- Without Rock Ridge the name is the ISO name without the version suffix
  `;1` and without a final dot, in lowercase. Directories have the mode
  0555, files 0444, and the owner is root.
- `NM` gives the name. The continue flag joins several entries, and the
  flags for "." and ".." are recognized.
- `PX` gives the mode with the file type, the link count, the owner and the
  group. `PN` gives the device number of a device file.
- `SL` gives the target of a symbolic link. Its components are joined with
  slashes, except after a component with the continue flag, and the flags
  for the root, "." and ".." become "/", "." and "..".
- `TF` gives the modification time in the 7 byte or the 17 byte form.
  Without `TF` the time of the directory record applies. Both forms carry
  the offset from UTC, which the conversion removes (`lib/date.c`).
- `CE` names a continuation area, which is read and parsed next, up to 16
  areas of at most 64 KiB. `ST` ends an area.
- `CL` makes a file record stand for a directory that was relocated
  because of its depth, and the inode of the record is that directory.
  `RE` marks the relocated directory and the relocation directory, which a
  listing omits.

## Directories

A lookup and a listing walk the records of the directory extent one
logical block at a time. They omit ".", "..", associated files, records
marked `RE` and the further extents of a multi-extent file. The position
of a listing is the byte offset of the next record, which makes a listing
linear in the size of the directory. A listing does not stop between the
extents of one file.

## Root by label

`root=LABEL=ID` mounts as the root the ISO 9660 file system whose volume
identifier, without its trailing blanks, is `ID`. `mount_root` asks
`iso9660_has_label` of every CD drive and then of every other disk, and
repeats the search every 250 ms for up to ten seconds, since a USB device
may register late. The log line is `root: iso9660 on sr1`.

## Changes elsewhere

- `open` with write access to a regular file whose file system has no
  write operation fails with `EROFS`, as POSIX asks of a read only file
  system. Before, the open succeeded on the initrd and the write failed
  with `EINVAL`.
- `kernel/lib/date.c` converts between calendar dates and day numbers. It
  replaces the private copies of the FAT driver, of the real time clock and
  of the aarch64 platform code.

## Tests

The harness file `cd` with `mkcd SCRIPT` runs a script of the case that
writes the image. `tests/iso_tree.py` builds the trees of the cases and
writes the manifest of a tree. `/bin/isotest` prints the same manifest from
the mounted tree, one line per entry with the type, the permission bits,
the owner, the size, the time and the hash of the contents or the target of
a link, and the post script compares both.

- `iso9660` mounts a Rock Ridge image with long names, names with blanks and
  UTF-8, set id bits, an owner that xorriso sets, symbolic links with
  short, relative, dangling and long targets, a file of 3 MiB, a directory
  of 300 files and a directory twelve levels deep, which xorriso relocates
  with `CL` and `RE` because of `-compliance deep_paths_off`. The image
  also contains `CE` areas. `isotest` checks that `mmap` of the largest file
  returns what `read` returns, that a read at an offset does as well, and
  that creating, writing, opening for writing and removing fail with
  `EROFS`.
- `iso9660_plain` mounts an image without Rock Ridge, with ISO level 1
  names.
- `iso9660_root` boots with `root=LABEL=MINIOS_ROOT` from an image of the
  root tree of the build and runs `/bin/cat`, whose libraries the dynamic
  loader maps from the ISO 9660 file system.

The slab allocator retains the per processor magazines of the size
classes that the file system uses first, and the cases `iso9660` and
`iso9660_plain` allow 4 pages that remain allocated after the program
(`resident_pages=4`).

## Limits

- Joliet and the ISO 9660:1999 extensions are not read.
- Logical blocks other than 2048 bytes are refused.
- Device files are listed with their type and device number, but they
  open no driver.
- The multi-extent path is not covered by a test: xorriso writes several
  extents only for files of 4 GiB and more.
