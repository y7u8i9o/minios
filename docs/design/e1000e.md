# The e1000e network driver

Milestone S1 of `docs/plan/release-0.7.0.md` (D6 in `docs/plan/drivers.md`)
adds a driver for the Intel 82574L Gigabit Ethernet controller, which QEMU
emulates as the `e1000e` device. The driver is in `kernel/drivers/e1000e.c`
and is based on the *82574 GbE Controller Family* datasheet. It registers a
normal Ethernet interface with the network core, so ARP, IPv4, DHCP and the
protocols above them work on it without changes.

## Probe and initialisation

`net_init` calls `e1000e_init` after `virtio_net_init`. The driver takes the
first PCI function with the ID 8086:10d3, maps its register space (BAR 0)
uncached and enables bus mastering. It then resets the controller by setting
`CTRL.RST` and waits up to 10 ms for the bit to clear. The reset also stops
any DMA that the firmware may have left running.

The MAC address is read from words 0 to 2 of the EEPROM through the `EERD`
register. If the EEPROM does not respond within 10 ms, the driver uses
receive address register 0 instead, which the controller loads from the
EEPROM during reset. An all-zero address or one with the multicast bit set
is rejected.

The interface is named with the new helper `netif_free_name`, which picks the
first unused `ethN`. On a machine with both a virtio-net device and an
e1000e, the virtio-net device becomes `eth0` and the e1000e `eth1`.

## Descriptor rings

The driver uses one receive ring and one transmit ring, each with 32 legacy
descriptors in a page of its own. The buffers are 2048 bytes long and are
allocated two to a page with `pmm_alloc_dma_page`. The receive control
register selects 2048-byte buffers, accepts broadcasts and strips the CRC.
The transmit control register enables padding of short frames and uses the
collision settings that the datasheet recommends for full duplex.

- **Transmit.** `transmit` copies the frame into the buffer of the next free
  descriptor, releases the pbuf straight away, sets `EOP`, `IFCS` and `RS`,
  and advances `TDT`. Copying the frame means the driver never holds on to
  a pbuf, which keeps the ownership rules of the network core simple. At
  the packet rates of a virtual machine, the extra copy costs little.
  Descriptors are reclaimed in order once the controller has set `DD`.
- **Receive.** All receive descriptors are handed to the controller at start.
  `e1000e_service` walks the ring from `rx_next` for as long as `DD` is set,
  copies each valid frame into a pbuf and passes it to `netif_input`. Frames
  that span several descriptors, carry error bits or are shorter than an
  Ethernet header are counted as dropped. The driver then returns the
  processed descriptors by moving `RDT` to the descriptor just before
  `rx_next`.

## Interrupts and the network worker

Only `netd`, the network worker, touches the rings, so they need no lock. To
support this, drivers now register a service function with
`net_worker_add_service`. The worker calls every registered function once
per pass, after running its timers and before processing the input queue.
virtio-net was converted to the same mechanism; previously the worker
called `virtio_net_service` by name.

The interrupt handler reads `ICR`, which acknowledges all pending causes,
and wakes the worker. The driver enables interrupts for transmit
write-back, link status changes, the receive timer, the receive minimum
threshold and receive overruns. It uses MSI. The controller's MSI-X mode is
not used: it routes the causes through `IVAR` and makes acknowledgement more
involved, which brings no benefit with a single pair of queues. If MSI is
unavailable, or the kernel option `e1000e=poll` is given, a network timer
wakes the worker every 5 ms and the service function reads `ICR` itself.

The worker also checks the link state in `STATUS.LU` on every pass and logs
any change. `e1000e_stop` takes the interface down, flushes its ARP entries,
resets the controller and frees the rings and buffers. If the reset fails,
the memory is intentionally left allocated, because the controller might
still be using it.

## Tests

The `nic` file of a test case accepts an optional second word that selects
the QEMU device model, for example `dgram e1000e`. Without it, the harness
attaches `virtio-net-pci` as before.

- `net_e1000e` checks that `eth0` is the e1000e, that its MAC address was
  read from the EEPROM and matches the address the harness assigned, and
  that the link comes up. It then sends 640 raw frames to the echo peer,
  waiting for each batch to come back, resets the controller and verifies
  that every packet buffer was returned to the pool.
- `net_e1000e_poll` runs the same test with `e1000e=poll`.
- `net_e1000e_dhcp` runs `netdhcptest` over the e1000e using QEMU's
  user-mode network.

## Limits

- One queue pair, no checksum or segmentation offload and no jumbo frames.
- No VLAN filtering and no multicast reception: the multicast table is
  cleared, so the controller accepts only unicast and broadcast frames.
- Only the first 82574L in the machine is used.
