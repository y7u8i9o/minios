# The e1000e network driver

Milestone S1 of `docs/plan/release-0.7.0.md` (D6 of `docs/plan/drivers.md`)
adds a driver for the Intel 82574L Gigabit Ethernet controller, which QEMU
emulates as the `e1000e` device and which UTM offers as an alternative to
virtio-net. The driver lives in `kernel/drivers/e1000e.c` and follows the
*82574 GbE Controller Family* datasheet. It registers an ordinary Ethernet
interface with the network core, so ARP, IPv4, DHCP and everything above
work on it without change.

## Probe and initialisation

`net_init` calls `e1000e_init` after `virtio_net_init`. The driver binds
the first PCI function with the ID 8086:10d3, maps BAR 0 (the register
space) uncached and enables bus mastering. It then resets the controller
by setting `CTRL.RST` and waits up to 10 ms for the bit to clear; the reset
also stops any DMA left behind by the firmware.

The MAC address comes from words 0 to 2 of the EEPROM, read through the
`EERD` register. If the EEPROM does not answer within 10 ms, the driver
falls back to receive address register 0, which the controller fills from
the EEPROM at reset. An address that is zero or has the multicast bit set
is rejected.

The interface takes the first free name `ethN`, using the new helper
`netif_free_name`. On a machine that has both a virtio-net device and an
e1000e, the virtio-net device is `eth0` and the e1000e is `eth1`.

## Rings

The driver uses one receive ring and one transmit ring of 32 legacy
descriptors each, one page per ring. Buffers are 2048 bytes, allocated two
per page with `pmm_alloc_dma_page`. The receive control register is set to
2048-byte buffers, broadcast acceptance and CRC stripping; the transmit
control register enables padding of short frames and uses the collision
values that the datasheet recommends for full duplex.

- **Transmit.** `transmit` copies the frame into the buffer of the next
  free slot, frees the pbuf immediately, sets `EOP`, `IFCS` and `RS` and
  advances `TDT`. Copying keeps the pbuf ownership rules of the network
  core simple and costs little at the frame rates of a virtual machine.
  Completed descriptors (`DD` set) are reclaimed in order.
- **Receive.** All descriptors are given to the controller at start.
  `e1000e_service` walks the ring from `rx_next` while `DD` is set, copies
  each good frame into a pbuf and hands it to `netif_input`. A frame that
  spans several descriptors, carries errors or is shorter than an Ethernet
  header is counted as dropped. The returned descriptors are given back by
  moving `RDT` to the descriptor before `rx_next`.

## Interrupts and the network worker

The rings are only touched by `netd`, the network worker, so they need no
lock. To make that possible, drivers now register a service function with
`net_worker_add_service`; the worker calls each registered function once
per pass, after the timers and before the input queue. virtio-net was
converted to the same mechanism, which replaces the direct call of
`virtio_net_service` in the worker.

The interrupt handler reads `ICR`, which acknowledges the causes, and kicks
the worker. The driver enables the causes for transmit write-back, link
status change, receive timer, minimum threshold and overrun. It uses MSI;
the controller's MSI-X mode is not used because it routes causes through
`IVAR` and complicates acknowledgement for no benefit with one queue pair.
Without MSI, or with the kernel option `e1000e=poll`, a network timer
wakes the worker every 5 ms and the service function reads `ICR` itself.

The link state is read from `STATUS.LU` on every pass and logged when it
changes. `e1000e_stop` takes the interface down, flushes its ARP entries,
resets the controller and frees the rings and buffers; if the reset fails,
the memory is deliberately not freed because the device may still access
it.

## Tests

The `nic` file of a case takes an optional second word that selects the
QEMU device model, for example `dgram e1000e`; without it the harness
attaches `virtio-net-pci` as before.

- `net_e1000e` checks that `eth0` is the e1000e, that its MAC address came
  from the EEPROM and equals the harness address, and that the link comes
  up. It then sends 640 raw frames to the echo peer, waits for each batch
  to return, resets the controller and checks that every packet buffer
  went back to the pool.
- `net_e1000e_poll` runs the same test with `e1000e=poll`.
- `net_e1000e_dhcp` runs `netdhcptest` on the e1000e with QEMU's user mode
  network.

## Limits

- One queue pair, no checksum or segmentation offload, no jumbo frames.
- No VLAN filtering and no multicast filter: the multicast table is
  cleared, so only unicast and broadcast frames are received.
- Only the first 82574L in the machine is used.
