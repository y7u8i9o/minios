# Early kernel and console (M1)

## Serial

`drivers/serial.c` drives COM1 at 115200 8N1 with polled output. Line feeds
are expanded to carriage return plus line feed on the wire.

## Framebuffer console

`drivers/fbcon.c` uses the first Limine framebuffer if it is 32 bits per
pixel RGB. The 8x16 font in `drivers/font.c` is generated by
`tools/genfont/genfont.py` from the X11 misc-fixed 7x14 bitmap font
(`tools/genfont/7x14.pcf.gz`, public domain) and covers ISO 8859-1. Each 7x14
glyph sits in the 8x16 cell with one blank row above and below.
The console keeps a shadow character buffer (up to 256x128 cells) and redraws
every row when it scrolls. The cursor is the current cell drawn inverted.
With `video=WxH@N` on the command line each glyph pixel is drawn as an N by
N block (`bootinfo.fb_scale`), so the text keeps its size on a high density
display; a scale that leaves fewer than 40x12 cells is ignored. The console
draws into `fb_screen` (`display.md`); when a GPU driver owns the display it
records the rectangle it drew and a kernel thread flushes it every 20 ms.
`fbcon_screen_changed` re-initializes the grid after a mode change.

## Console layer

`drivers/console.c` fans output out to serial and, when present, the
framebuffer. Output is serialized by `console_lock`, taken with the irqsave
variant because `kprintf` runs before the boot CPU structure exists. Once
`panic_in_progress` is set the lock is bypassed so a CPU that panics while
printing can still report.

`kprintf` and `kvprintf` are built on `lib/printf.c`, a callback based
formatter supporting `%d %i %u %x %X %p %s %c %%`, the `l`, `ll` and `z`
length modifiers, the `-` and `0` flags and a field width. `ksnprintf` uses
the same core.

## Segmentation

`arch/x86_64/gdt.c` installs five descriptors plus a 64 bit TSS:

| Selector | Segment |
|---|---|
| 0x08 | kernel code |
| 0x10 | kernel data |
| 0x18 | user data |
| 0x20 | user code |
| 0x28 | TSS |

The order of the user descriptors is fixed by `sysret`, which loads `SS` from
`STAR[63:48] + 8` and `CS` from `STAR[63:48] + 16`. The TSS `rsp0` points at
the boot stack and `IST1` at a dedicated 8 KiB double fault stack.

## Interrupts

`arch/x86_64/isr.S` generates 256 entry stubs. Vectors that do not push an
error code push a zero so every entry reaches `isr_common` with the same
layout. `isr_common` saves the general purpose registers into a
`struct trapframe` and calls `trap_dispatch`. Exceptions print a register
dump (including `CR2` and `CR3`) and call `panic_trap`. The legacy PICs are
remapped to vectors 32 to 47 and fully masked. Interrupts stay disabled until
the timer milestone.

## Panic and power

`debug/panic.c` prints the message, a backtrace, and then either exits QEMU
through isa-debug-exit with code 1 (`CONFIG_PANIC_EXIT=1`) or halts.

`arch/x86_64/power.c`: `power_off` writes `0x2000` to port `0x604` (the q35
ACPI PM1a control register), falls back to isa-debug-exit and finally halts.
`power_reboot` pulses the 8042 reset line and falls back to a triple fault
through an empty IDT. Both are unconditional. The orderly shutdown sequence
arrives in M15.

## Test

`tests/cases/exception` boots with `test=exception`, executes `ud2` and checks
that the serial log contains the `#UD` name, `RIP=`, `RSP=` and the panic
line. `tests/cases/boot` checks the boot banner and the formatter.
