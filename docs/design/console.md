# Early kernel and console (M1)

## Serial

`drivers/serial.c` drives COM1 at 115200 8N1 with polled output. Line feeds
are expanded to carriage return plus line feed on the wire.

## Framebuffer console

`drivers/fbcon.c` uses the first Limine framebuffer if it is 32 bits per
pixel RGB. The 8x16 font in `drivers/font.c` is generated by
`tools/genfont/genfont.py` from the X11 misc-fixed 7x14 bitmap font
(`tools/genfont/7x14.pcf.gz`, public domain) and covers ISO 8859-1. Each 7x14
glyph sits in the 8x16 cell with one blank row above and below.
The console keeps a shadow character buffer (up to 256x128 cells) and redraws
every row when it scrolls. A parallel attribute byte stores each cell's
foreground (low nibble) and background (high nibble) palette indices.
The 16-colour palette follows the Terminal window except that index 7
keeps the console's original `0xaaaaaa`. SGR supports reset, bold/normal,
reverse/normal, default foreground/background and normal/bright colours
(`0 1 22 7 27 30-37 39 40-47 49 90-97 100-107`). Up to eight CSI
arguments are retained. Scroll, erase and resize preserve or reset
attributes together with characters. The cursor is the current cell
drawn inverted; `fbcon_get_cell` exposes both buffers to display tests.
With `video=WxH@N` on the command line each glyph pixel is drawn as an N by
N block (`bootinfo.fb_scale`), so the text keeps its size on a high density
display; a scale that leaves fewer than 40x12 cells is ignored. The console
draws into `fb_screen` (`display.md`); when a GPU driver owns the display it
records the rectangle it drew and a kernel thread flushes it every 20 ms.
`fbcon_screen_changed` re-initializes the grid after a mode change.

## Console layer

`drivers/console.c` fans output out to serial and, when present, the
framebuffer. Early output uses `console_lock` with irqsave because it can
run before CPU structures exist. After startup, kernel output enters
per-CPU rings, drained by `consoleout`; polled serial writes happen outside
the framebuffer spinlock. `/dev/console` writes instead flush queued echo
and diagnostics and hold `console_drain_mutex` for their entire output.
This lossless ordered path prevents process migration between CPUs from
reordering terminal cursor sequences and leaving duplicated command text.
Once `panic_in_progress` is set, panic printing bypasses the normal lock.

`kprintf` and `kvprintf` are built on `lib/printf.c`, a callback based
formatter supporting `%d %i %u %x %X %p %s %c %%`, the `l`, `ll` and `z`
length modifiers, the `-` and `0` flags and a field width. `ksnprintf` uses
the same core.

## Segmentation

`arch/x86_64/gdt.c` installs five descriptors plus a 64 bit TSS:

| Selector | Segment |
|---|---|
| 0x08 | kernel code |
| 0x10 | kernel data |
| 0x18 | user data |
| 0x20 | user code |
| 0x28 | TSS |

The order of the user descriptors is fixed by `sysret`, which loads `SS` from
`STAR[63:48] + 8` and `CS` from `STAR[63:48] + 16`. `STAR[63:48]` is 0x13,
the kernel data selector with RPL 3: Intel processors OR 3 into the two
selectors, AMD processors do not, so the RPL must already be in the base.
With 0x10, an AMD processor under KVM ran user code with `SS` = 0x18, and
the first `iretq` back to user mode after a page fault faulted with
`#GP(0x18)` because `SS.RPL` differed from `CS.RPL`; QEMU's TCG follows
the Intel rule and did not show it. AMD processors also leave the cached
`SS` attributes unchanged on `sysret`; that has no effect on this kernel's
64 bit only user programs. The TSS `rsp0` points at the boot stack and
`IST1` at a dedicated 8 KiB double fault stack.

## Interrupts

`arch/x86_64/isr.S` generates 256 entry stubs. Vectors that do not push an
error code push a zero so every entry reaches `isr_common` with the same
layout. `isr_common` saves the general purpose registers into a
`struct trapframe` and calls `trap_dispatch`. Exceptions print a register
dump (including `CR2` and `CR3`) and call `panic_trap`. The legacy PICs are
remapped to vectors 32 to 47 and fully masked. Interrupts stay disabled until
the timer milestone.

## Panic and power

`debug/panic.c` halts the other CPUs, writes the console text still queued
in the per CPU rings to the serial port (`console_panic_drain`), prints the
message and a backtrace, and then either exits QEMU through isa-debug-exit
with code 1 (`CONFIG_PANIC_EXIT=1`) or halts. The drain goes to the serial
port only, because the console daemon may have been halted in the middle of
a framebuffer update; `fbcon_write` finishes a pending scroll before it
draws, and `fbcon_draw_glyph` ignores positions outside the screen. The
halt IPI cannot stop a CPU that is already inside a fault of its own, so a
second CPU entering `panic` parks itself silently and the first report,
with its frame and backtrace, still completes; only a nested panic on the
reporting CPU prints `nested panic:` and exits at once.

For a fault in kernel mode, `panic_trap` also prints `trap_dump_extra`
(`arch/x86_64/idt.c`): the six words at the stack pointer (the frame a
failing `iretq` was consuming), the live segment selectors, `CR0`, `CR4`,
`EFER`, GDTR, IDTR, the GDT entries, both GS base registers, the `syscall`
MSRs, the TSS `rsp0`, and the values the CPU pushed at the last entry from
user mode on that CPU (`cpu.last_user_*`, recorded by `trap_dispatch` and
`syscall_dispatch`). The boot log prints the CPU vendor, family, model and
the hypervisor signature (`cpu_log_identity`), so output from emulation
and from hardware virtualization can be told apart.

`arch/x86_64/power.c`: `power_off` writes `0x2000` to port `0x604` (the q35
ACPI PM1a control register), falls back to isa-debug-exit and finally halts.
`power_reboot` pulses the 8042 reset line and falls back to a triple fault
through an empty IDT. Both are unconditional. The orderly shutdown sequence
arrives in M15.

## Test

`tests/cases/exception` boots with `test=exception`, executes `ud2` and checks
that the serial log contains the `#UD` name, `RIP=`, `RSP=` and the panic
line. `tests/cases/boot` checks the boot banner and the formatter.
